# 남은 전체 작업과 운영 데이터 확인 — 2026-09-09

사용자 질문: 기존 운영 사이트는 행사 정보와 이미지를 서버에 업로드했으므로 서버에 추가 자료가 있을 것 같다. 전체 개편에서 무엇이 남았는가?

이번 작업은 상태 확인과 기록이다. 운영 서버에 접속하지 않았고, 제품 코드·DB·이미지를 변경하거나 이전하지 않았다. 앞서 “사진과 브랜드 자산 마감이 남았다”는 답변은 디자인 기준이며 전체 운영 전환 완료를 뜻하지 않는다.

## 현재 파일로 확인한 데이터 구조

- `database.js:10`–`20`: 레거시 런타임 DB는 `data/events.db`이다. 루트 `events.db`를 현재 행사 원본으로 사용하지 않는다.
- `database.js:25`, `:57`: `events`, `highlights`에 한영 행사 정보와 이미지 경로, 링크 등을 저장한다.
- `server.js:53`, `:319`–`364`: 현재 업로드 구현은 `public/images/uploads/YYYY-MM/`에 WebP 본문과 썸네일을 저장한다. DB 안에 사진 파일 자체를 넣는 방식이 아니다.
- `.gitignore:27`–`29`: 현재 업로드와 과거 `public/images/highlights/uploads/`는 Git 대상에서 제외된다. 과거 업로드 경로와 외부 이미지 URL도 운영 DB의 실제 참조를 기준으로 확인해야 한다.
- 현재 업로드 구현은 최대 1600px 본문/480px 썸네일로 변환하고 업로드 원본을 보관하지 않는다. 서버에 사진이 있더라도 촬영 원본 해상도까지 확보됐다고 단정할 수 없다. 실제 운영 버전과 파일 상태는 확인 전이다.
- `web/src/content/center.ts:83`과 `media.ts:2`: 새 공개 사이트는 로컬 한영 콘텐츠와 기존 사진 7개를 사용한다. 운영 행사 DB와 아직 연결되지 않았다.

따라서 Git 저장소에 있는 자료만으로 운영 콘텐츠 전체를 확보했다고 볼 수 없다. 실제 행사 수, 비공개/비활성 기록, 업로드 수량, 누락 파일, 외부 링크 생존 여부는 아직 모른다. 새 촬영을 확정하기 전에 운영 서버 보유 자료부터 확인하는 순서가 적절하다.

## 끝난 범위

- 공개 홈·센터 소개·프로그램·전시/체험·활동 기록·굿즈 소개·방문 안내의 화면 구성과 최신 UI/UX 개선.
- Pretendard 로컬 폰트, UI용 Lucide SVG, Heroicons/Bootstrap 원본 및 라이선스 관리.
- 한영·라이트/다크, 제목/내비/스크롤 모션, 푸터 아이콘, 상단 진행 게이지, 카드·CTA·마키·반응형 구현.
- 공개 프런트엔드 디렉터리 구조와 `.gitignore` 정리. 향후 백엔드 폴더를 미리 만들었다는 뜻은 아니다.
- 해당 공개 구현의 로컬 검사와 Chrome/WebKit 검증. 직전 프로덕션 Playwright 141개 통과 기록은 [최신 구현 인수인계](../handoff/2026-09-08-motion-footer-next.md)에 있다.

원본 TODO10의 1/3/4/5/6/7/8/9/10에 해당하는 첫 시안 작업은 후속 구현/검증/폰트·SVG 정리로 이행됐다. 2번의 화면 구성은 구현됐지만 최종 대표 사진·브랜드 자산 선택과 최종 디자인 승인을 완료로 합치지 않는다. 원본 TODO10은 첫 디자인 단계의 목록이며, 전체 백엔드·운영 기능 완료표가 아니다. 원본 문서와 부록은 수정하지 않았다.

## 남은 작업 순서

| 순서 | 범위 | 실제 남은 일과 완료 기준 |
| --- | --- | --- |
| 1 | 운영 자료 확인·보존 | 먼저 서버의 실제 실행 버전, SQLite 경로/행사·활동 기록, 이미지와 기존 URL을 읽기 전용으로 목록화한다. 이후 일관된 DB 사본과 연결 이미지의 백업·복구를 검증한다. Git 사본이나 공개 API 목록만으로 전량 확보를 판단하지 않는다. |
| 2 | 공개 콘텐츠·브랜드 마감 | 확보한 기존 사진부터 대표 공간·참여 장면·굿즈 사진을 선별하고 부족한 것만 촬영한다. 최종 SVG 로고를 받아 파비콘/홈 화면 아이콘·공유 이미지를 마감한다. 사진 크롭/배치와 실제 행사 날짜·내용·활동 기록 목적지, 한영 사실을 대조한다. |
| 3 | 관리자·백엔드 | 공개 디자인 다음 단계에서 마스터 1명→일반 관리자 생성, 로그인·세션·권한, 행사/활동 기록 편집과 이미지 업로드를 구현한다. 홈페이지 콘텐츠 편집 범위와 세부 권한은 그 시점의 필요한 결정만 확인한다. |
| 4 | PostgreSQL/Prisma·데이터 연결 | 승인된 스택으로 기존 SQLite를 옮길 스키마·변환·되돌리기 절차를 만든다. 운영 사본으로 리허설하고 건수·ID·한영 필드·날짜/기간·정렬/공개 상태·이미지 참조를 대조한다. 공개 페이지를 실제 데이터에 연결한다. 이전 중 추가된 운영 자료의 반영도 포함한다. |
| 5 | 공개 전 검증 | 실제 자료를 넣은 화면과 관리자 흐름을 검증한다. 실기기 모바일, 접근성/성능, 이미지 누락, 기존 `/walletExperence` 및 행사/이미지 URL 보존·이전 경로를 확인한다. 운영 도메인의 HTTPS·canonical/hreflang·OG·sitemap과 검색 공개 설정을 점검한다. 현재 프리뷰는 noindex/robots 차단을 유지한다. |
| 6 | 수동 운영 전환 | 운영 환경에 맞는 수동 배포·백업·복구·롤백 절차를 준비하고 최종 승인 후 실행한다. GitHub Actions는 사용하지 않으며 `deploy.yml.disabled`를 보존한다. |

현재 사용자 질문은 위 작업의 현황 확인이다. 백엔드 구현·서버 데이터 수집·운영 이전·배포를 이번 턴에 시작하라는 승인으로 해석하지 않는다.

## 이후 별도 기능 단계

상점·밋업 신청·예약·결제는 이번 공개 디자인 범위 밖이며 아직 구현하지 않았다. 사용자의 “지금 만들라는 뜻이 아니다”는 범위 정정이며, 원래 합의한 장기 방향이 취소된 것은 아니다.

원본 15개 답변에 따라 회원/비회원 허용 선택, 선착순/운영자 승인제, 원화 고정/BTC 고정 가격, 라이트닝 결제, 이메일 알림 방향을 보존한다. 토스 원화 수납, 배송/수령, 취소·환불 정책, 정책별 적용 범위는 아직 확정되지 않았다. 첫 공개에 이 기능까지 반드시 넣어야 한다고 가정하지 않는다.

## 이번 확인의 증거와 한계

- 브랜치는 `redesign/center-web`. 기존 dirty/untracked 상태와 `web/`를 보존했다.
- 직전 manifest의 소스·설정·자산·테스트 2568개와 사진 7개의 현재 SHA-256을 대조해 누락/불일치 0개를 확인했다. reference fingerprint: `182389382a6dddb6960a82d41bd27f7104d27aca0aff48a454b4dc4124c385d4`.
- 결과: `evidence/remaining-work-2026-09-09/local-state.json`. 이번 턴에 빌드·브라우저·테스트를 다시 실행했다는 뜻은 아니다.
- 독립 담당 `remaining_scope_check`는 원본 확정 답변/TODO와 최신 인수인계를 읽기 전용으로 교차 확인했다. 총괄은 실제 레거시 저장 코드·새 공개 콘텐츠·검색 설정·파일 해시를 확인했다.
- 운영 서버의 데이터 존재/수량/복구 가능성은 미검증이다. 운영 접속, 실제 결제/메일, 배포, stage/commit은 수행하지 않았다.
