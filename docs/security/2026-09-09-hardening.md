# SQLite·관리자 보안 개선 — 2026-09-09

대상은 `redesign/center-web`의 새 `web/` 서비스다. SQLite를 유지하고 기존 관리자 비밀번호를 해시로 전환하며, 실제 운영 적용은 별도 수동 릴리스로 남긴다. 운영 서버·기존 환경 파일·운영 데이터에는 접근하거나 변경하지 않았다. 보존된 루트 Express 앱은 새 서비스의 실행 경로에 포함하지 않는다.

## 데이터와 인증

- `better-sqlite3`를 13.0.3으로 고정했고, 실제 연결의 `sqlite_version()`은 3.53.4다. 기존 3.50.4에 해당했던 WAL-reset 결함의 수정 버전을 사용한다. [SQLite WAL 설명](https://www.sqlite.org/wal.html), [드라이버 릴리스](https://github.com/WiseLibs/better-sqlite3/releases/tag/v13.0.3)
- 기존 SQLite 파일·행사/하이라이트 ID와 필드를 유지한다. 관리자 세션에 마지막 사용 시각·자격 증명 버전만 추가하며, 기존 세션은 재로그인해야 한다. 소수 관리자가 단일 호스트에서 콘텐츠를 편집하는 현재 범위에는 새 PostgreSQL 서비스가 필요하지 않다. [SQLite 용도](https://www.sqlite.org/whentouse.html)
- 서버는 원문 `ADMIN_PASSWORD` 대신 `ADMIN_PASSWORD_HASH`만 받는다. 기존 비밀번호를 그대로 입력해 고유 salt 16바이트의 scrypt 검증값(N=131072, r=8, p=1, 출력64바이트)을 만든다. 검증값도 공개하거나 로그에 남기지 않는다. [OWASP 비밀번호 저장 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 비밀번호와 세션 검증을 분리했다. 무작위32바이트 토큰의 SHA-256만 DB에 보관한다. 로그아웃,30분 미사용,발급8시간 경과,비밀번호 검증값 변경 시 세션이 무효화된다. HTTPS 쿠키는 HttpOnly·Secure·SameSite=Strict이며 Domain을 지정하지 않는다.
- 운영 로그인은 명시적으로 신뢰한 프록시가 전달한 유효 IP별로 제한한다. nginx가 연결 IP로 전용 헤더를 덮어쓰고, 앱 포트는 외부에서 접근할 수 없어야 한다. 임의 X-Forwarded-For/X-Real-IP는 사용하지 않는다. 프록시 설정 없는 HTTPS 로그인은 거부한다.
- KDF는 한 번에 하나만 실행하고 실행·대기 중인 요청을 서로 다른 클라이언트 합계8개로 제한한다. 같은 클라이언트의 중복 요청과 가득 찬 대기열은429다. 한 클라이언트의 검증 중 다른 클라이언트의 정상 로그인은 짧게 대기한 뒤 처리한다. 각 클라이언트는15분간5회 제한을 가진다. 같은 NAT 주소의 관리자는 제한을 공유하며, 분산 서비스 거부 공격까지 앱 하나로 해결한다고 주장하지 않는다.
- 루프백 HTTP 검토 서버는 신뢰할 외부 프록시가 없어 전체 제한을 유지한다. 생성된 검토 비밀번호 원문은 로컬 테스트 fixture에만 남고 앱 프로세스에는 전달하지 않는다. 운영 자격 증명으로 사용하면 안 된다.

## 브라우저와 운영 경계

HTML 응답마다 새 nonce를 만들며 운영 스크립트 CSP에는 unsafe-inline/unsafe-eval을 허용하지 않는다. 테마 초기화에도 nonce를 전달한다. 모션과 동적 스타일을 위해 인라인 스타일은 허용한다. 이미지·네트워크는 필요한 로컬 출처로 제한하고, 프레임·object·외부 form/base를 차단한다. API·자산에는 실행을 허용하지 않는 기본 정책을 적용한다. HTTPS 설정일 때 HSTS를 보낸다. nonce 때문에 HTML은 요청마다 동적으로 생성된다.

개발 HMR·테마·페이지 갱신은 확인했다. 개발 도구의 선택적 버전 조회·외부 폰트 요청은 CSP가 차단한다. 운영 빌드에는 해당 도구가 없다. 기본 Playwright 설정에서도 trace·screenshot·video를 끄므로 인증 요청이 실패 증거에 자동 수집되지 않는다.

온라인 백업은 최신 WAL 커밋과 스냅샷이 참조하는 이미지, 파일 해시를 한 비공개 디렉터리에 보존한다. 복구 점검은 새 임시 경로만 사용한다. 비밀번호 변환·백업·nginx·PM2의 구체적인 설정은 [운영 절차](operations.md)에 있다. 실제 TLS/방화벽/권한/프록시/로그 회전/외부 백업 스케줄은 아직 운영 서버에 적용하지 않았다. nginx는 로컬에 설치되어 있지 않아 호스트의 `nginx -t`와 TLS 검증이 필요하다.

## 감사 범위와 남아 있는 구버전 문제

Codex Security Standard 감사는 수정 전 커밋 `727a88228c172bab7b5293bf1a46dd0382c28d0a`의 읽기 전용 복사본에 수행했다. 일반 소스·설정248개와 SVG2,413개를 검토했다. 역사 문서·바이너리·환경 파일·런타임 자료248개는 제외했다. 운영 환경과 당시 Playwright 추적의 실제 비밀번호 마스킹은 검증하지 않아 공식 보고서의 coverage는 partial이다. 기록은 로컬 `.local/security-2026-09-09/baseline/`에 보존했다. 이 감사는 수정 후 빌드의 검증 결과와 구분한다.

루트 잠금 파일의 별도 npm 감사에는37개 경고(critical1/high22/moderate7/low7)가 남아 있다. 이 수는 직접적인 런타임 공격 경로37개를 뜻하지 않는다. 보존된 구버전의 의존성과 스크립트를 새 standalone 산출물·실행 경로에 넣지 않아야 한다. 운영이 아직 구버전인 상태를 “전체 보안 해결”로 표시하지 않는다. 구버전 기본 비밀번호를 운영에서 사용한 적이 있다면 기존 비밀번호 유지 대신 교체가 필요하다.

## 입력 포커스

필드의 투명 outline을 미리 확보하고 색상만240ms로 바꾼다. 레이아웃 이동 없이 키보드 포커스를 유지한다. 동작 줄이기·강제 색상 모드에서는 즉시 표시하며, 설정이 바뀌면 진행 중인 효과도 즉시 중단한다. 로그인·행사·하이라이트·공지 입력, 두 테마와 세 화면 폭을 확인한다.
